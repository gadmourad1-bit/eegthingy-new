# GeoAdaptNet family harmonized-v2 procedure track

## Status and scope

`ieee_mi.geoadapt_v2` is the cache/protocol-bound adapter for the three
GeoAdaptNet registry identities:

| Stable ID | Runtime key | Frozen representation/configuration |
|---|---|---|
| `architecture.geoadaptnet` | `geoadapt` | four deterministic fixed-band SPD covariances; full GeoAdaptNet anchor plus residual |
| `architecture.geoadaptnet_fb` | `geoadapt_fb` | harmonized broadband EEG; four learned Sinc filters; `reduced_dim=None` |
| `architecture.geoadaptnet_fbsp` | `geoadapt_fbsp` | harmonized broadband EEG; four learned Sinc filters; `reduced_dim=8` |

This is a **separate procedure track**, identified in every plan, record, CSV,
and summary as `separate_procedure_geoadapt_harmonized_v2`. It is not an
additional common-recipe raw-architecture column. Historical GeoAdaptNet
scores use different loaders and/or fit protocols and cannot fill this grid.

No benchmark scores are embedded in the runner or this document. Scores exist
only after a complete score-blind grid is joined to outcomes by the companion
analysis module.

The N/A cells are structural:

- All three models are N/A on BNCI2014-001 because their main heads are
  binary, whereas the registered task is four-class.
- Fixed GeoAdaptNet is N/A on BNCI2014-004. Its frozen residual path uses
  `reduced_dim=8`, and the constructor requires the reduced dimension not to
  exceed the channel count. A dataset-conditioned three-dimensional variant
  would not be the registered frozen method.
- GeoAdaptNet-FBSP is N/A on BNCI2014-004. The supplied cache has three bipolar
  channels, while the stable identity requires `reduced_dim=8`. Clamping the
  dimension to three would disable the spatial-reduction path and alias the
  result to GeoAdaptNet-FB. The runner rejects this cell before cache access or
  training.

The N/A rules are published as rows in `not_applicable.csv`; they are not
zeroes, failed experiments, or missing results.

## Input and feature contract

All eligible cells use `ieee-mi-cache-v2/harmonized`:

- local Exp4 uses its deployment-valid 256-sample interval;
- the public cohorts use the harmonized 320-sample interval;
- all inputs are 128 Hz;
- no PhysioNet confirmation subject S55-S109 is opened;
- Lee2019, Weibo2014, and Zhou2016 remain outside this adapter.

Channel scaling is fit twice:

1. the selection scaler uses training rows only and transforms training and
   validation;
2. the final scaler uses training plus validation and transforms final-source
   and test rows.

Left/right channel-pair statistics are pooled through the shared
`ieee_mi.data.fit_channel_scaler` contract. Test trials never influence either
scaler.

### Deterministic four-band SPD view

Fixed GeoAdaptNet derives these four bands:

`8-12`, `11-15`, `14-20`, and `20-30 Hz`.

Each 65-tap Hamming FIR is generated by
`scipy.signal.firwin(..., pass_zero=False, scale=True)`. Trials are
reflection-padded by 32 samples, convolved once, and demeaned. Per-band
covariances are calculated in float64, divided by the epoch length, shrunk by
`0.001` toward `trace(C)/channels * I`, symmetrized, given a scale-aware
positive eigenvalue floor sized for float32 roundoff, and stored in memory as
float32. Positivity is checked again on the actual float32 matrices; a
representable diagonal margin is added if casting consumed the first margin.
Zero, constant, rank-deficient, and extremely small inputs are regression
tests for this persisted-dtype guarantee.

The FIR and covariance operations fit no cross-trial state. The only
source-fitted operation before this view is the appropriate source-only
channel scaler. The immutable plan stores the exact FIR coefficient digest and
full transform contract. Each record stores hashes of its scaled arrays and
derived SPD arrays.

GeoAdaptNet-FB and FBSP consume the source-scaled broadband trials directly.
Their Sinc filters and covariance maps are learned inside the reset/refit
procedure; they do not consume the fixed SPD view. For each learned band, the
implementation demeans the signal, divides its spatial covariance by the
number of samples, normalizes to unit trace, shrinks by `0.05` toward `I/C`,
and adds the deterministic channel-index ramp `diag(linspace(0, 0.02, C))`.
The full FB path applies the matrix logarithm at the identity reference and
upper-triangle vectorization; it does not fit or apply a train-set SPD
recentering reference. FB is channel-count generic. The frozen FBSP identity
additionally requires a genuine reduction from `C` to 8, so it is eligible
only when `C > 8`.

## Frozen training configurations

No CLI flag can silently alter a stable-ID configuration.

### GeoAdaptNet

- `bands=4`, `reduced_dim=8`, `band_width=24`, `fusion_width=32`;
- dropout `0.25`, epsilon `1e-5`, reference momentum `0.05`;
- residual gate initialization `0.02`, no auxiliary intent head;
- AdamW, learning rate `3e-4`, weight decay `1e-3`;
- at most 180 selection epochs, patience 25, minimum improvement `1e-4`;
- batch size 64, label smoothing `0.05`, gradient clipping `5.0`;
- unsmoothed validation cross-entropy selection; no augmentation or deep
  supervision.

### GeoAdaptNet-FB and FBSP

- four 65-tap Sinc filters warm-started exactly at the fixed four bands;
- dropout `0.25`, epsilon `1e-5`;
- FB uses `reduced_dim=None`; FBSP uses the literal value 8;
- AdamW, learning rate `1e-3`, weight decay `1e-3`;
- at most 250 selection epochs, patience 40, minimum improvement `1e-4`;
- batch size 64, label smoothing `0.05`, gradient clipping `5.0`;
- unsmoothed validation cross-entropy selection and no reflection augmentation.

The Sinc parameters are unconstrained logits over sequential feasible
intervals. Each low-cutoff interval begins strictly above the preceding low;
each high-cutoff interval begins above both its low plus the minimum bandwidth
and the preceding high. The upper intervals reserve space for remaining
bands. The inverse-logit initialization reconstructs the four stated
warm-start bands. Initialization rejects infeasible bands, and the
parameterization preserves low order, high order, minimum bandwidth, and
Nyquist bounds after optimizer perturbations.

Training loss uses label smoothing `0.05` for all three identities. Epoch
selection deliberately uses **unsmoothed** validation cross-entropy for all
three identities. Fixed GeoAdaptNet obtains this from `deepnet.engine`;
FB/FBSP use an explicit zero-smoothing selection loss. This removes the former
selection-objective mismatch while preserving the frozen training objective.

Seeds are installed before model construction and again before final refit.
All three paths use PyTorch's strict deterministic-algorithm mode with
`warn_only=False`. cuDNN benchmarking and both cuDNN/matmul TF32 are disabled,
cuDNN deterministic mode is enabled, and float32 matmul precision is
`highest`. CUDA execution additionally requires
`CUBLAS_WORKSPACE_CONFIG=:4096:8` before Python starts. If any setting cannot
be installed, the job fails before fitting; there is no warning-only fallback.
The effective settings are recorded in every job artifact.

## Reset/refit and held-out boundary

Each atomic job executes this sequence:

1. install its seed and construct a fresh model;
2. hash the complete initial state;
3. optimize on training rows and select the epoch count on validation
   cross-entropy;
4. hash the selected state;
5. restore the complete initial state and verify its hash exactly;
6. refit on training plus validation for `selected_epoch_index + 1` epochs,
   using the original full cosine-schedule horizon;
7. invoke the held-out probability path exactly once;
8. publish only held-out row indices and float64 class probabilities.

The internal prepared-job object has source labels but deliberately has no
`y_test` member. Fixed GeoAdaptNet receives synthetic container targets only
because its prediction DataLoader requires a target-shaped field; actual test
outcomes have already been discarded at that boundary.

Selection objective values, held-out labels, predicted labels, and performance
metrics are forbidden recursively from producer records.

## Immutable provenance and power-cut recovery

`plan.json` binds:

- exact dataset, subject, fold, seed, eligibility, and stable-ID contracts;
- every harmonized cache identity and label-free split-row hash;
- complete stable-ID model/training configurations;
- full canonical model-registry records for those stable IDs;
- the four-band FIR/covariance contract and coefficient hash;
- source hashes for the runner, analyzer, data/configuration code, complete
  GeoAdaptNet implementations, `pyproject.toml`, and `uv.lock`;
- the portable UV compute contract: Python implementation/version,
  architecture, complete package inventory, Torch/CUDA/cuDNN build versions,
  and deterministic settings;
- a 50 GiB default output-filesystem low-water mark.

The plan intentionally contains no hostname, GPU UUID, or node-local device
inventory. Those values vary across a cluster and are recorded separately
under each job's `node_inventory`. This permits another conforming node to
execute a job without weakening the portable software/compute identity.

Every plan write, load, worker start, audit, and analysis entry point runs the
production semantic validator. It requires the literal four-dataset roster,
five seeds, three exact stable-ID configurations, five exact N/A cells and
reasons, preprocessing/scaling contracts, per-ID counts
`2,150/2,195/2,150`, and exactly 6,495 unique jobs. Recomputing a checksum
cannot legitimize a semantically altered plan. Registry eligibility is checked
against the same matrix; fixed GeoAdaptNet and FBSP are explicitly ineligible
on BNCI2014-004 while FB remains eligible.

The canonical plan and SHA-256 companion are prepared together in a durable
transaction directory, then published with atomic no-replace renames. Resume
can finish a cut between the two final renames; malformed legacy or staging
residue is quarantined. Exact scalar types are enforced throughout the plan,
so Python-equal substitutions such as `true` for `1` or `50` for `50.0`
cannot legitimize a forged plan.

Claims, failures, analysis gates, and publication locks are likewise written
to fsynced, read-only staging files and atomically renamed into authority.
Output first enters a nonce-bound `partials/` directory. Its `record.json`,
`predictions.npz`, and `completion.json` are fsynced and checksum-bound, then
moved beside the final destination, sealed and fsynced as an exact `0555`
directory, and atomically renamed into `records/`. A power cut can therefore
leave:

- a valid record plus a stale claim;
- an unpublished partial;
- an invalid partial/record.

Recovery validates durable completions before moving definitively dead,
same-host claims and partials into timestamped `quarantine/` paths. It also
quarantines torn staging files and malformed legacy authorities before a safe
retry. A valid claim owned by a foreign or otherwise unknown process remains
frozen; positive claim-stealing timeouts are forbidden. This avoids
duplicating a long job merely because another node is temporarily unreachable.

Artifact reads walk no-follow directory descriptors and open leaves with
`O_NOFOLLOW|O_NONBLOCK`. Regular leaves must have exactly one hard link.
Symlinks, FIFOs, devices, sockets, replaced lock inodes, and hard-linked
aliases fail closed. Final record and analysis-directory moves use an atomic
no-replace primitive; a claim lost at the final commit boundary causes the
renamed record to be quarantined. Record validation holds the sealed directory
inode and opens all three child descriptors before reading any child. The
validator retains those descriptors through all reads, binds exact bytes to
validation, decoding, hashes, and metrics, and then rebinds each child name to
the same inode. Full directory `dev/ino/mode/nlink/size/mtime_ns/ctime_ns` and
exact sorted child-stat fingerprints must match before and after the package
read. This rejects leaf toggles and coherent A/B/A package substitution even
when the original names are restored. Writable final directories/files are
rejected, and NPZ ZIP members and NumPy arrays require exact order and
cardinality, so duplicate members cannot be silently selected. Quarantine and
failure evidence has its own exact, checksum-bound ledger schema.

Every stale, malformed, corrupt, partial, claim, gate, lock, or analysis
recovery carries the `(dev, ino)` captured when that candidate was enumerated
or validated into the final quarantine rename. If another process replaces
the name, recovery reports contention and leaves the replacement untouched.
Analysis-lock recovery reads and validates the exact enumerated lock inode
before it may interpret that lock's nonce or touch its referenced partial; a
lock A-to-B substitution therefore cannot cause B's partial to be recovered
under A's authority. Claim release likewise carries the exact record inode
published by that invocation. Loss or replacement of the claim can hide only
that inode, never whichever valid record happens to occupy the canonical name
later.
If a no-replace helper moves the validated inode and then raises while
verifying, recovery recognizes the exact destination binding and completes
the same-inode hide/quarantine rather than losing forensic ownership.

Every CUDA claim and final record rename is enclosed by the shared GPU
registry guard, which keeps the registry fence locked and validates the exact
physical-UUID lease both before and after the authoritative filesystem
mutation. The detached lease receipt is persisted unchanged in the claim and
record. Loss of the fence, lease inode, nonce, owner, or receipt aborts the
operation; an already-renamed result is quarantined.

Immediately before and after every authoritative record commit, the runner
reloads and byte-compares the canonical plan; rebinds source, registry, UV
project/environment, the job's live cache and split, claim/device inventory,
and exact GPU-lease receipt; and fails closed on any drift. Publication state
is inferred from the destination's binding to the staged `(dev, ino)`, not
from a rename helper returning normally. Thus a move-then-raise fault marks
the exact record as published, performs the same post-commit authority/device
rebind as a normal return, and quarantines only that inode before the error
escapes. The exact published inode tuple is the sole publication-state flag;
there is no separate Boolean/identity assignment window.

The output filesystem is probed through an opened directory descriptor. The
literal 50 GiB low-water mark is rechecked immediately before every record,
prediction, completion, aggregate table, ledger, manifest, and final rename;
it is not merely a startup estimate.

`audit` is complete only when all 6,495 planned records validate and there are
no missing/corrupt/unknown records, live or stale claims, unknown claims, or
partials.

## UV-only execution

The final project must have a generated and frozen `uv.lock`.
`pyproject.toml` must list exactly pinned NumPy, SciPy, scikit-learn, and
PyTorch runtime dependencies. Every dependency group must also be exactly
pinned: Pytest lives in `[dependency-groups].test`, while ReportLab,
pdfplumber, and pypdf live in `[dependency-groups].docs`. Neither group is a
production runtime dependency.
Planning cross-checks every direct pin against the lock's project
`requires-dist` ledger and every `requires-dev` group, rejects unresolved or
orphaned lock packages, and hashes both the complete reachable lock closure
and the runtime-only transitive closure. It also requires an active isolated
UV virtual environment whose installed distributions exactly equal that
runtime-only closure: extra packages and the test/docs groups are rejected.
The runner never calls `pip`, `uv sync`, or an installer.

Create and synchronize the production environment without modifying the
system Python and without installing optional groups or the local project
distribution:

```bash
uv venv .venv
uv sync --frozen --no-default-groups --no-install-project
```

Use separate UV environments for tests or PDF/document generation, adding
only `--group test` or `--group docs` as appropriate. Example from the
already synchronized runtime-only production environment:

```bash
export UV_CACHE_DIR=/home/hanafy/scratchpad/eeg_novel_20260729/uv-cache
export CUBLAS_WORKSPACE_CONFIG=:4096:8
export OMP_NUM_THREADS=4
export MKL_NUM_THREADS=4
export OPENBLAS_NUM_THREADS=4
export NUMEXPR_NUM_THREADS=4
export VECLIB_MAXIMUM_THREADS=4
export BLIS_NUM_THREADS=4
export TBB_NUM_THREADS=4
export NUMBA_NUM_THREADS=4

uv run --frozen --no-sync --no-default-groups python -m ieee_mi.geoadapt_v2 plan \
  --run-root /path/to/runs/geoadapt_v2 \
  --cache-root /path/to/data_cache \
  --minimum-free-gib 50 \
  --worker-cpu-threads 4
```

Before launching workers, inspect `nvidia-smi` and coordinate with other
workstation users. Each CUDA worker pins one physical GPU through visibility
and participates in the repository-wide lease registry. The registry rejects
duplicate physical UUIDs and caps all concurrent IEEE-MI runners together at
three GPUs, leaving the fourth GPU unleased by default. It does not preempt
unrelated non-project processes. GeoAdapt requires exactly one complete
`GPU-...` UUID in `CUDA_VISIBLE_DEVICES`; numeric ordinals, UUID prefixes, and
multi-GPU visibility are rejected because they do not provide an unambiguous
physical-device identity:

Immediately after lease acquisition and before each claim, the worker also
queries UUID, utilization, memory, and compute-process rows through
`nvidia-smi`. A foreign compute PID or utilization above the idle threshold
fails closed. The same process/UUID check is repeated before commit while
allowing the owning worker's active CUDA context.

```bash
CUDA_VISIBLE_DEVICES=GPU-UUID-HERE \
uv run --frozen --no-sync --no-default-groups python -m ieee_mi.geoadapt_v2 worker \
  --run-root /path/to/runs/geoadapt_v2 \
  --cache-root /path/to/data_cache \
  --device cuda:0
```

Lease contention exits with status 75 so a scheduler can retry it. Registry
corruption or loss of the owned lease fails closed.

Optional `--stable-ids` partitions the three stable IDs among workers.
`--max-jobs` is useful for a preflight. Full cache verification runs at worker
startup by default; `--skip-full-cache-preflight` leaves per-job verification
enabled and does not weaken the final analyzer audit.

Audit without scoring:

```bash
uv run --frozen --no-sync --no-default-groups python -m ieee_mi.geoadapt_v2 audit \
  --run-root /path/to/runs/geoadapt_v2
```

## Score-joining analysis

Only after the audit is exact and quiescent:

```bash
uv run --frozen --no-sync --no-default-groups python -m ieee_mi.geoadapt_v2_analysis \
  --run-root /path/to/runs/geoadapt_v2 \
  --cache-root /path/to/data_cache \
  --output-root /path/to/runs/geoadapt_v2_analysis
```

The analyzer takes an exclusive cross-process analysis/publication gate before
the quiescence audit. Workers check the same coordination lock before creating
a claim. Cache paths and outcomes are not opened until the gate is held and
the exact score-blind grid has passed audit; the gate remains held through
score joining, the second audit, captured-ledger verification, and atomic
publication. For every job, one held record-directory descriptor supplies the
exact `record.json`, `predictions.npz`, and `completion.json` byte snapshot
through the runner's sole simultaneous-descriptor completion primitive. Rows,
probabilities, validation, and the input ledger all consume those same held
bytes and their SHA-256 digests—not a detached validator or later path reread.
Live-path hashing is used solely to verify that captured ledger before and
after metric computation, immediately before publication, and after the
committed output rename while both fences remain held. A dead same-host gate
or publication lock is recoverable after a power cut; foreign/unknown owners
remain frozen.

Publication accepts no caller-created `AnalysisResult`, cache loader, metric
configuration, or seal. After acquiring its publication lock it reloads the
live plan, revalidates the source closure, registry, UV project/environment,
formal decisions, cache identities and split identities, and recomputes every
table from the immutable prediction archives with the default cache loader.
No detached analysis result can be supplied to this boundary. It repeats the
static, cache, audit, captured-ledger, and ownership checks before an
exact-schema, exact-cardinality, canonical-byte publication and repeats the
live captured-ledger check after commit. The full plan/source/environment/
cache/split authority and both held fences are rebound in one boundary check
immediately before and after the final rename. Score joining owns no GPU lease;
GPU identity is therefore rebound at record commits, while analysis explicitly
rejects any stray GPU authority. Publication identity is still determined
independently of helper return, so move-then-raise, post-commit input,
ownership, or lock-release failures quarantine only the exact staged output
inode. Move-then-raise also executes the same post-publication rebind before
cleanup, and the exact inode tuple is the sole output-publication state. ECE
is fixed at 15 bins in code and has no CLI override.

The analysis output must be outside the immutable run directory. It publishes:

- fold/job metrics;
- concatenated-fold subject-seed metrics;
- seed-averaged subject metrics;
- subject-averaged dataset summaries;
- equal-dataset overall summaries;
- a three-dataset common-support summary;
- paired common-support contrasts with uncertainty and multiplicity control;
- timing/resource summaries;
- explicit N/A cells;
- the path/digest-only prediction input ledger;
- an immutable manifest binding all output files and the input ledger.

Metrics are accuracy, balanced accuracy, chance-normalized balanced accuracy,
macro F1, Cohen kappa, one-vs-rest macro AUROC, negative log likelihood,
multiclass Brier score, and 15-bin expected calibration error.

Aggregation is prespecified:

1. concatenate test folds within subject and seed;
2. average seeds within subject;
3. average subjects within dataset;
4. give each eligible dataset equal weight.

Fixed GeoAdaptNet and FBSP overall rows therefore cover three datasets, not
four. The dataset-coverage column makes this explicit. Trial outcomes and
probability matrices are not published by the analyzer.

The prespecified common support is local Exp4, Cho2017, and PhysioNet MI. For
the primary inferential metric, balanced accuracy, seeds are first averaged
within subject. Point estimates give each of the three datasets equal weight.
Uncertainty uses a deterministic dataset-stratified paired-subject bootstrap
with 10,000 resamples and percentile 95% intervals. Pairwise model tests use
20,000 two-sided subject sign-randomization draws on the equal-dataset
contrast. The three predeclared pairwise model comparisons receive Holm
family-wise multiplicity correction. Other metrics remain descriptive; this
procedure does not manufacture post-hoc p-values for every output column.

## Interpretation limits

- All four scored cohorts are already-opened development evidence. None is a
  new confirmation population.
- The three GeoAdapt identities use model-specific procedure contracts and
  are not directly exchangeable with the common raw architecture grid.
- BNCI2014-004 contains supplied bipolar derivations. It must not be described
  as independent point-electrode or interpolation evidence.
- A high score would not by itself establish global state of the art,
  clinical readiness, or novelty. Those claims require prespecified
  comparators, uncertainty, external confirmation, ablations, and an honest
  prior-art analysis.
